# SmartGas Grid 数据库架构设计

## 1. 架构概述

SmartGas Grid 采用 **混合数据架构**，结合传统关系型数据库和向量数据库，支撑业务数据管理和智能问答功能。

```
┌─────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────┐      ┌─────────────────────────────┐  │
│  │   SQLite (关系型)    │      │    ChromaDB (向量数据库)      │  │
│  │   ┌───────────────┐ │      │   ┌─────────────────────┐   │  │
│  │   │ 核心业务数据   │ │      │   │  语义知识库         │   │  │
│  │   │  - 站场信息    │ │      │   │  - 管网自然语言描述  │   │  │
│  │   │  - 管线信息    │ │──────┼──▶│  - 调度操作手册     │   │  │
│  │   │  - 应急事件    │ │ 同步  │   │  - 应急预案         │   │  │
│  │   │  - 设备明细    │ │      │   │  - 分输站资料       │   │  │

│  │   ┌───────────────┐ │      │   用途: RAG语义检索          │  │
│  │   │ 明细数据表     │ │      │   算法: Gemini Embedding    │  │
│  │   │  - 干线/支线   │ │      │   维度: 768维              │  │
│  │   │  - 压缩机     │ │      │                             │  │
```

## 2. SQLite 关系型数据库

### 2.1 数据库配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 数据库类型 | SQLite | 轻量级嵌入式数据库 |
| ORM 框架 | SQLModel | 基于 SQLAlchemy 的现代 ORM |
| 数据文件 | `backend/data/smartgas.db` | 本地文件存储 |
| 连接池 | 默认 | 适用于中等并发场景 |

### 2.2 数据表结构

#### 核心业务表

| 表名 | 说明 | 主要字段 |
|------|------|----------|
| `stations` | 站场信息 | id, name, type, longitude, latitude, design_pressure |
| `pipelines` | 管线信息 | id, name, start_station_id, end_station_id, diameter, length, category |
| `emergency_events` | 应急事件 | id, event_type, location, severity, status, description, created_at |

#### 明细数据表（对应 Excel 导入模板）

| 表名 | 说明 | 数据来源 |
|------|------|----------|
| `trunk_pipeline_details` | 干线管道明细 | 干线管道 Sheet |
| `branch_pipeline_details` | 支线管道明细 | 支线管道 Sheet |
| `node_relation_details` | 管道站场阀室关系 | 管道站场阀室关系 Sheet |
| `distribution_point_details` | 分输口明细 | 分输口 Sheet |
| `compressor_details` | 压缩机明细 | 压缩机 Sheet |
| `storage_details` | 储气库明细 | 储气库 Sheet |
| `dispatch_console_details` | 调度台明细 | 调度台 Sheet |

## 3. ChromaDB 向量数据库

### 3.1 设计目的

为 RAG（检索增强生成）系统提供语义检索能力，支持自然语言问答。

### 3.2 配置信息

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 数据库类型 | ChromaDB | 开源嵌入式向量数据库 |
| 存储路径 | `backend/data/chroma_db` | 本地持久化存储 |
| 集合名称 | `smartgas_knowledge` | 单一集合存储所有知识 |
| 嵌入模型 | Gemini Embedding-001 | Google 提供的嵌入服务 |
| 向量维度 | 768 维 | 固定维度 |
| 相似度算法 | 余弦相似度 | 默认相似度度量 |

### 3.3 数据同步流程

```
┌──────────────┐    ┌──────────────────┐    ┌──────────────────┐
│   SQLite     │    │   文本转换模块    │    │    ChromaDB      │
│   业务数据    │───▶│  (db_to_text.py) │───▶│   向量知识库      │
└──────────────┘    └──────────────────┘    └──────────────────┘
                           │
                           ▼
                    ┌──────────────┐
                    │ 自然语言描述  │
                    │  - 站场:     │
                    │    "中卫站是  │
                    │     气源站,   │
                    │     经度..."  │
                    │  - 管线:     │
                    │    "中贵线从  │
                    │     中卫到..."│
                    └──────────────┘
```

### 3.4 文档存储格式

每个文档包含以下元数据：

```json
{
  "id": "node-001",
  "text": "站场: 中卫站 (ID: C-001)\n- 类型: 气源站\n- 位置: 经度 105.18°, 纬度 37.5°",
  "metadata": {
    "name": "中卫站",
    "station_type": "source",
    "longitude": 105.18,
    "latitude": 37.5
  }
}
```

## 4. RAG 知识库架构

### 4.1 混合检索策略

```
用户提问
    │
    ▼
┌─────────────────────────────────────────┐
│          RAG Service                    │
│  ┌─────────────────────────────────┐   │
│  │  1. 应急预案知识库 (关键词匹配)  │   │
│  │     - 压力下降/管线断裂/阀门故障 │   │
│  │     - 最高优先级               │   │
│  └─────────────────────────────────┘   │
│                   │ 未匹配              │
│                   ▼                     │
│  ┌─────────────────────────────────┐   │
│  │  2. Text-to-SQL (精确查询)      │   │
│  │     - Gemini 生成 SQL          │   │
│  │     - 查询 SQLite 数据库        │   │
│  └─────────────────────────────────┘   │
│                   │ 无结果              │
│                   ▼                     │
│  ┌─────────────────────────────────┐   │
│  │  3. 向量检索 (语义搜索)          │   │
│  │     - Embedding 向量化          │   │
│  │     - ChromaDB 相似度搜索        │   │
│  └─────────────────────────────────┘   │
│                   │ 无结果              │
│                   ▼                     │
│  ┌─────────────────────────────────┐   │
│  │  4. Fallback (兜底回复)         │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 4.2 知识来源

| 来源 | 类型 | 存储位置 | 用途 |
|------|------|----------|------|
| 管网站点/管线数据 | 结构化数据 | SQLite → ChromaDB | 基础管网知识 |
| 应急预案手册 | 硬编码 | Python 字典 | 快速应急响应 |
| 调度台应知应会 | 文档 | ChromaDB (待导入) | 操作规范问答 |

## 6. 技术选型说明

### 6.1 为什么选择 SQLite？

| 优势 | 说明 |
|------|------|
| 零配置 | 无需独立服务器，文件即数据库 |
| 易备份 | 单文件复制即可完成备份 |
| 跨平台 | 支持 Windows/Linux/macOS |
| 足够用 | 当前数据规模（<10万条）完全适用 |

### 6.2 为什么选择 ChromaDB？

| 优势 | 说明 |
|------|------|
| 嵌入式 | 与应用同进程，零网络延迟 |
| Python原生 | 与 FastAPI 项目无缝集成 |
| 免费开源 | Apache 2.0 协议 |
| 规模适配 | <1000万向量的场景性能优秀 |

### 6.3 未来扩展方向

| 当前限制 | 扩展方案 |
|----------|----------|
| SQLite 单机 | 迁移至 PostgreSQL |
| ChromaDB 单机 | 迁移至 Qdrant/Pinecone |
| 数据规模 < 100万 | 考虑 Milvus 分布式方案 |
