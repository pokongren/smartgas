# 智脉底座：三库合一数据库架构说明

> [!NOTE]
> **一句话总结：** 咱们这儿不是一个库在战斗，是“海陆空”三军联动：关系型存身家，向量型存知识，图引擎存关系。

### 1. 到底有哪几个库？（三库全景）

别听那些虚的，咱们这儿清清楚楚三个大库：

1.  **第一库：关系数据库 (The RDBMS)**
    - **存什么**：站场名字、经纬度、管线压力、设计输量……这些一板一眼的硬核台账。
    - **怎么查**：标准的 SQL API。AI 会自己写 SQL 进去翻，比你手查快多了。
2.  **第二库：向量知识库 (ChromaDB)**
    - **存什么**：几千页的《安全守则》、《调度规程》、历年事故案例。
    - **怎么查**：向量相似度匹配。你问“起火了咋办”，它直接从几百万字里把那一段“灭火方案”给你抠出来。
3.  **第三库：拓扑图数据库 (Graph Engine)**
    - **存什么**：谁连着谁。这不是表，这是一张巨大的“网”。
    - **怎么查**：NetworkX 算法。算“卡脖子”站场、算“断流影响面”，全靠它。

### 2. 数据库性能参数（严谨版）

| 数据库 | 作用域 | 典型延迟 | 关键指标 |
| :--- | :--- | :--- | :--- |
| **SQLite/MySQL** | 基础台账 | < 10ms | 事务一致性，确保数据不错行。 |
| **ChromaDB** | 知识检索 | < 100ms | 召回率 (Recall)，确保护航规程不漏查。 |
| **NetworkX** | 拓扑计算 | < 50ms | 连通性分析，支持万级节点秒级遍历。 |
| **Memory Index** | Excel 缓存 | < 5ms | 解决大批量原始数据实时查询痛点。 |

### 3. 为什么非得“三库合一”？

以前的系统，查台账要去台账系统，查规程要去 OA，算影响要去仿真软件。咱们这儿通过 **MCP 智能总线** 把这三者全拧到了一起。
大模型就是那个“中枢”，它知道什么时候该去哪个库里掏宝贝。这就叫“数据不孤岛，业务全闭环”。
