# 靖边截断 → 输气路径变化仿真 · 技术方案

> 文档状态：草稿 | 创建时间：2026-03-16

---

## 一、背景与目标

**靖边**是陕京系列管线的气源枢纽，承担以下管线的首站角色：

| 管线 | 靖边节点 | 节点类型 |
|------|---------|---------|
| 陕京四线 | 陕京靖边首站（ID: 958） | distribution |
| 西一线 | 西一靖边压气站 | compressor |
| 陕京一/二/三线 | 陕京靖边首站 | distribution |

**目标**：当靖边被截断（停气/检修/事故）时，自动计算并可视化：
1. 哪些下游分输站无法正常供气
2. 系统能否通过其他路径绕行补气
3. 绕行路径是什么、额外增加多少管道长度

---

## 二、现状评估

### ✅ 已具备能力

| 模块 | 文件 | 能力 |
|------|------|------|
| 拓扑图构建 | `topology_computation.py` | 构建 networkx 有向图 |
| 最短路径 | `POST /topology/path` | Dijkstra / A* / Bellman-Ford |
| 节点排除 | `PathRequest.exclude_nodes` | 已支持，直接可用 |
| 备选路径 | `POST /topology/paths` | 返回多条备选路径 |
| 断流传播 | `simulation_service.py` | BFS 断流扩散仿真 |

### ❌ 缺口（需新增）

1. **跨管线联通图**：各管线 JSON 是独立的，靖边在不同管线中是不同节点，图中没有互联
2. **联络点定义表**：明确哪些节点物理上是同一地点（如"陕京靖边首站" ↔ "西一靖边压气站"）
3. **截断对比 API**：返回截断前/后路径差异，包括受影响节点列表
4. **前端交互**：点选节点截断，高亮显示原路径、绕行路径、断供节点

## 三、实现方案

### 3.1 第一步：定义跨管线联络点

在 `backend/data/` 下新建 `network_connections.json`：

```json
{
  "junction_groups": [
    {
      "name": "靖边枢纽",
      "node_ids": [958, "西一靖边压气站ID", "陕一靖边首站ID"],
      "description": "陕京系列和西一线共同起点"
    },
    {
      "name": "高丽营末站",
      "node_ids": [22863, 60641],
      "description": "陕四干线末站 ↔ 大唐煤制气管道末站"
    }
  ]
}
```

### 3.2 第二步：多管线联合图构建服务

新增 `POST /topology/build-network`：

```python
# 伪代码逻辑
def build_network(pipeline_jsons: list, connections: list):
    G = nx.DiGraph()
    for pipeline in pipeline_jsons:
        # 添加各管线节点和边
        add_pipeline_to_graph(G, pipeline)
    for group in connections:
        # 合并联络点（用第一个节点 ID 代表该枢纽）
        merge_junction_nodes(G, group["node_ids"])
    return G
```

### 3.3 第三步：截断推演 API

新增 `POST /topology/simulate-cutoff`：

**请求体：**
```json
{
  "graph_name": "national_network",
  "cutoff_node": "958",
  "target_nodes": ["22863", "60641", "87185"],
  "algorithm": "dijkstra"
}
```

**响应体：**
```json
{
  "before": {
    "paths": { "22863": ["958", "...中间节点...", "22863"] }
  },
  "after": {
    "paths": { "22863": ["其他气源", "...", "22863"] },
    "unreachable": ["某分输站ID"]
  },
  "diff": {
    "rerouted": ["22863"],
    "supply_lost": ["某分输站ID"],
    "extra_length_km": 120.5
  }
}
```

### 3.4 第四步：前端可视化

在 `TopologyView.tsx` 或新建 `CutoffSimView.tsx`：

- **交互流程**：
  1. 用户点击地图/梯形图上的节点
  2. 右键菜单 → "模拟截断"
  3. 系统调用 `/topology/simulate-cutoff`
  4. 高亮渲染：

| 颜色 | 含义 |
|------|------|
| 🔴 红色节点 | 截断点（靖边） |
| ⚫ 灰色路径 | 原路径（截断前） |
| 🟢 绿色路径 | 绕行路径（截断后） |
| 🟠 橙色节点 | 受影响但有替代供气 |
| ❌ 深红节点 | 完全断供，无法绕行 |

## 四、开发优先级

```

├── 手工定义靖边联络点

Phase 3（前端可视化，3-5天）
├── 截断交互 UI
├── 路径高亮渲染
└── 差异信息面板
```

## 五、核心风险

> [!WARNING]
> **最大风险**：各管线间的物理联络关系（哪些节点是同一地点）需要**领域知识确认**，纯靠节点名称字符串匹配可能误合并或漏合并。

> [!NOTE]
> 当前拓扑是**有向图**（单向流动），若气源切换需要反向流动（如从下游反输），需要考虑边的方向问题，可能需要改为无向图或补充反向边。
