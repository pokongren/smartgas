# 靖边截断 → 输气路径变化仿真 · 技术方案

> 文档状态：**v2 更新** | 更新时间：2026-03-18 | 基于后端数据库化重构

## 一、背景与目标

**靖边**是陕京系列管线的气源枢纽，承担以下管线的首站角色：

| 管线 | 靖边节点 ID | 节点名称 | 节点类型 |
|------|-----------|---------|---------|
| 陕京四线 | `SJ4_TRUNK-S-0` | 陕京靖边首站 | distribution |
| 西一线 | `WE1-S-33` | 西一靖边压气站 | compressor |

**目标**：当靖边被截断（停气/检修/事故）时，自动计算并可视化：
1. 哪些下游分输站无法正常供气
2. 系统能否通过其他管线路径绕行补气
3. 绕行路径是什么、额外增加多少管道长度

## 三、实现方案

### 3.1 跨管线联络点（Phase 1）

> [!IMPORTANT]
> 这是最关键的一步——需要**领域知识**确认物理联络关系。

在数据库新增 `junction_groups` 表：

```sql
CREATE TABLE junction_groups (
    id INTEGER PRIMARY KEY,
    name VARCHAR NOT NULL,           -- 枢纽名称
    description VARCHAR,
    station_ids JSON NOT NULL        -- 关联的 station ID 列表
);

-- 初始数据
INSERT INTO junction_groups VALUES
(1, '靖边枢纽', '陕京系列和西一线共同起点', '["SJ4_TRUNK-S-0", "WE1-S-33"]'),
(2, '高丽营', '陕四干线末站 ↔ 大唐煤制气管道末站', '["SJ4_TRUNK-S-50", "SJ4_B2-S-11"]');
```

**自动发现策略**：基于数据库坐标距离小于 0.01° (约 1km) 且跨不同管线系统的站场，自动推荐联络候选。

### 3.2 联合拓扑图构建（Phase 1）

在 `topology_computation.py` 中新增方法：

```python
def build_national_network(self, session) -> TopologyGraph:
    """构建全国联合拓扑图（含跨管线联络边）"""
    # 1. 读取全量站场和管段
    stations = session.exec(select(Station)).all()
    pipelines = session.exec(text("SELECT ...")).all()
    
    # 2. 构建基础图
    graph = self.build_graph("national", nodes, edges, directed=False)
    
    # 3. 读取联络点，添加虚拟互联边
    junction_groups = session.exec(select(JunctionGroup)).all()
    for group in junction_groups:
        ids = json.loads(group.station_ids)
        for i in range(len(ids)):
            for j in range(i+1, len(ids)):
                graph.add_edge(TopoEdge(
                    id=f"JUNCTION-{group.id}-{i}-{j}",
                    source=ids[i], target=ids[j],
                    edge_type=EdgeType.INTERCONNECT,
                    length_km=0.1  # 虚拟短边
                ))
    return graph
```

### 3.3 截断推演 API（Phase 2）

新增 `POST /api/topology/simulate-cutoff`：

```python
@router.post("/topology/simulate-cutoff")
def simulate_cutoff(request: CutoffRequest, session = Depends(get_session)):
    """
    请求: { cutoff_nodes: ["SJ4_TRUNK-S-0", "WE1-S-33"],  -- 截断靖边相关所有节点
            target_nodes: ["SJ4_TRUNK-S-50"],  -- 关注的下游节点（高丽营）
            algorithm: "dijkstra" }
    
    响应: {
        before: { paths: { "SJ4_TRUNK-S-50": PathResult } },
        after:  { paths: { "SJ4_TRUNK-S-50": PathResult | null },
                  unreachable: ["某分输站ID"] },
        diff:   { rerouted: [...], supply_lost: [...], extra_length_km: 120.5 }
    }
    """
    service = TopologyComputationService()
    graph = service.build_national_network(session)
    
    # 截断前：正常路径
    before_paths = {}
    for target in request.target_nodes:
        result = graph.find_path(source, target)
        before_paths[target] = result
    
    # 截断后：排除节点后重新路径
    after_paths = {}
    unreachable = []
    for target in request.target_nodes:
        result = service.find_path("national", source, target, 
                                   exclude_nodes=request.cutoff_nodes)
        if result:
            after_paths[target] = result
        else:
            unreachable.append(target)
    
    return { "before": before_paths, "after": after_paths, 
             "unreachable": unreachable, ... }
```

### 3.4 前端可视化（Phase 3）

在 `GlobalPipelineView.tsx` 或新建 `CutoffSimView.tsx`：

**交互流程**：
1. 用户右键地图站点 → "模拟截断"
2. 系统自动查找该站场所属的联络组
3. 调用 `POST /api/topology/simulate-cutoff`
4. 地图高亮渲染：

| 样式 | 含义 |
|------|------|
| 🔴 红色脉冲节点 | 截断点（靖边） |
| ⚫ 灰色虚线 | 原路径（截断前） |
| 🟢 绿色动画路径 | 绕行路径（截断后） |
| 🟠 橙色节点 | 受影响但有替代供气 |
| ❌ 深红闪烁节点 | 完全断供，无法绕行 |

## 五、核心风险

> [!WARNING]
> **最大风险**：跨管线联络关系需要**领域知识确认**。坐标自动匹配只是辅助，最终需人工审核。

> [!NOTE]
> 当前拓扑是**有向图**（单向流动），截断绕行需要改为**无向图**（`directed=False`），否则无法发现反向补气路径。`TopologyGraph` 已支持无向模式。

> [!CAUTION]
> 当前 9 条管线是 **9 个独立的连通分量**（无跨管线边），在添加联络边之前，`find_path` 甚至无法找到跨管线路径。Phase 1 必须先完成。
